# THE SILICON MAN

A shared procedural world for visitor-created agents. Five philosophical choices shape a deterministic personality and a stable avatar. Agents walk, think and converse when they meet; those conversations create memories and relationships. This is a fictional character experience.

## Run and storage

For Render hosting and X credential setup, see [RENDER.md](./RENDER.md). `render.yaml` configures a Node service with persistent SQLite storage, automatic startup migrations and the same shared-world/X behavior.

Requires Node 22.13+. Run `npm install`, `npm run dev`, `npm test` and `npm run typecheck`. `npm run build` creates the Vinext/Cloudflare Workers bundle. The project uses React 19, TypeScript, React Three Fiber and procedural geometry.

The default authoritative backend is Cloudflare D1, declared as `"d1":"DB"` in `.openai/hosting.json`. Sites provisions this binding and applies generated Drizzle migrations when publishing. No external database credentials are needed. Local development must use the declared D1 binding and apply the SQL files in `drizzle/` in journal order to its local database. Add schema changes in `db/schema.ts`, run `npm run db:generate`, inspect the SQL and metadata, and retain applied migrations unchanged. Application requests seed the five founding characters idempotently; migrations contain only schema work.

D1 failures remain connection errors. The application never substitutes an independent local world for an unavailable shared backend. Existing browser demo storage is kept only for an explicit legacy import and its archived history. New public agents are actual shared database records; no synthetic visitor population is added.

## Ownership and creation

API requests are rate limited at the Cloudflare Worker entry point using atomic, shared D1 counters and fixed windows. Each IP gets 240 API requests per minute, with additional shared limits of 5 creation/import attempts per hour, 60 history requests per minute and 10 X linking requests per minute. These count attempts, including invalid requests and retries. IPs behind the same network share these limits. Cookie resets do not reset counters. Cloudflare's edge IP header is used; local previews share a single bucket. Only IP hashes are stored, and expired counters are removed in bounded batches. Excess requests return HTTP 429 with `Retry-After`; database failures return 503 before application work. Apply migration `0003_free_thunderbolts.sql` before serving the updated Worker. The D1 binding is required for rate limiting even when using the optional Supabase world adapter.

The initial world request establishes an opaque guest cookie with HttpOnly, SameSite=Lax and Secure on HTTPS. The server stores its SHA-256 hash privately. Public snapshots contain every saved agent and never include cookie tokens, owner hashes or session records. Creation derives traits and five stored beliefs on the server, accepts exactly five answer indexes, validates names, and uses a unique owner constraint to make retries return the existing agent. Cross-origin POST requests are rejected. Clearing the cookie loses ownership access; public profile links remain read-only. Cross-device recovery is not implemented.

Legacy browser profiles can explicitly select **Bring [name] into the world**. The client infers the original three choices only when they reproduce the exact saved traits. Import retains the unused UUID, name and canonical personality, creates fresh global memories, and rejects an identity already present in the database. Previous fictional demo conversations remain on the device. Import never claims another global agent or overwrites its identity.

## Shared motion and conversation

Visible clients poll and request an awaited tick every four seconds. A conditional D1 update grants one 30-second world lease; competing requests read the current snapshot. A transaction updates only the agents included in that tick under the matching lease, so concurrent creations cannot be overwritten. There is no process timer, background promise or unattended catch-up backlog.

Each tick wakes at most 500 saved agents, prioritizing ongoing conversations and rotating others by persisted last-awake time. Snapshots still include every saved agent; the rest display Resting. Movement follows the connected 64-unit-radius graph and neighboring waypoints, with seeded destination offsets and distance-based durations. The five outer districts provide additional gathering places. Browser rendering interpolates saved movement plans without per-frame database writes. A shared spatial-grid resolver then gives every displayed body at least 1.12 world units of center clearance, including crossing paths and coincident endpoints. Detailed avatars, batched avatars, labels, facing and camera follow all consume the same resolved positions. Walking agents yield sideways smoothly; directed right-hand route lanes reduce head-on conflicts before correction. Goal following and avoidance share a hard 1.05-unit-per-second cap based on monotonic frame delta, with resumed frames capped to50ms. Snapshot clock corrections cannot reset displayed positions. Cached waypoint progress carries agents around bends even when they lag behind server time. Identical polling plans, reordered records and growing scene buffers retain this progress; large formation placement runs only when an agent first appears. The resolver checks the shared registry of every solid scenery footprint, including trees, rocks, buildings, benches, lamps, shrubs, ponds and the First Body, and keeps bodies within the world boundary. Swept checks protect each travelled segment as well as its endpoint. An internal precision margin keeps Float32 render coordinates outside the authored footprints. New arrivals choose clear positions against current inhabitants, and meetings persist separated stopping positions. These changes preserve saved identities and do not introduce additional paid calls.

Up to six disjoint nearby pairs can start a scripted conversation per tick. Partners must actually be within three world units, stop walking, and speak four saved lines over 24 seconds. Character and pair cooldowns prevent immediate repeats. Worldview answers inform the authored exchanges. Thoughts update with activity or recent memories and carry their scripted source. Encounters are canonically retained in D1; each public snapshot includes the latest 250, while `/api/history?agent=id&before=timestamp` returns 50 retained conversations per page. Memories retain the latest five and relationships retain actual encounter counts.

## Optional Supabase and paid generation

An existing complete Supabase configuration remains supported. Apply `supabase/migrations/001_world.sql`, then `002_expanded_world.sql`, then `supabase/seed.sql`; existing installations need only the incremental migration. Set `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY` and server-only `SUPABASE_SECRET_KEY`. Partial configuration remains an error. This adapter verifies anonymous bearer sessions with Supabase, uses private service-role RPCs, and preserves RLS restrictions and durable budget reservations.

**The default D1 world uses scripted thoughts and conversations and makes no paid AI calls.** Paid OpenRouter generation is currently available only through the optional Supabase adapter with explicit `WORLD_MODE=shared-ai`, an API key and a supported model. No AI provider credentials were supplied for this deployment.

The retained paid path permits one global in-flight request, at least 30 seconds between starts, at most two starts per rolling minute, and conservative daily reservations (defaults: 100 starts, $1 allowance, $0.01 per attempted call). Uncertain failures keep their reservation and do not automatically retry. Live model capabilities/prices must support strict structured output and the conservative 4500-input/500-output token bound. Semantic validation limits output to the two canonical speakers, one memory each, and a bounded affinity change. Provider output cannot modify ownership or movement. Configure a provider-side spending cap as well. Live provider billing has not been verified.

## Optional X account linking

X linking supplements the existing `silicon_guest` ownership session; it does not replace Sites sign-in, claim an existing agent, or provide account recovery across browsers. The owning browser can attach one verified X profile to its existing agent. Public snapshots show only X ID, username, display name and link timestamp; separate relational records prevent simulation ticks from overwriting the link. An X ID can belong to only one agent at a time. Owners can unlink without X credentials being configured.

Enable OAuth 2.0 in an X developer **Web App** (confidential client), register the exact deployed `https://<site-host>/api/x/callback`, and configure server-only `X_CLIENT_ID`, `X_CLIENT_SECRET`, `X_CALLBACK_URL` through native Sites runtime secrets. No values belong in source or browser bundles. The callback URL must match this site's origin and `/api/x/callback` exactly; HTTP is accepted only for localhost previews. Append generated `drizzle/0002_brief_darkstar.sql` when applying pending local migrations; native publication applies hosted migrations separately. This schema change preserves existing identities and agent data.

`GET /api/x/status` returns `{configured}`. Owner-only, same-origin `POST /api/x/start` accepts `{agentId}` and returns `{authorizationUrl}`; `POST /api/x/unlink` accepts the same payload and returns the refreshed world. Callback redirects only to a fixed local successor path with `x=linked|cancelled|expired|already_linked|failed`. PKCE S256 state binds the guest owner and agent for ten minutes, supports one atomic claim, and is invalidated by a replacement attempt or unlink. The server exchanges the code, verifies the returned profile through `/2/users/me`, and discards the access token. It requests only `tweet.read users.read`, with no write or `offline.access` scope, and stores no access/refresh tokens. This verifies X account control at linking time; it does not assert X's paid verification badge or continually refresh username changes.

Implementation follows the official [X PKCE flow](https://docs.x.com/fundamentals/authentication/oauth-2-0/authorization-code) and [current-user endpoint](https://docs.x.com/x-api/users/get-my-user). Real D1 tests cover owner rejection, atomic concurrent state claims, expiry, replay, duplicate X IDs, replacement/unlink races and tick persistence. Provider exchange/profile validation is tested with controlled responses. Live X authorization requires configured developer credentials and a real user completing consent; mocked responses do not verify live X access.
